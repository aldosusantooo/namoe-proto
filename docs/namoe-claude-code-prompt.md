## Implementation notes that prevent common mistakes

- Device cookie: set it in `proxy.ts` (Next 16) or `middleware.ts` (Next 15) for page requests when missing, and again on the redirect response inside `/b/[token]` so a first-ever scan still stamps the right device. Not httpOnly, sameSite lax, 400 days.
- Upvote toggle must be one transaction: check the `Upvote` composite key, insert or delete, and increment or decrement `upvoteCount`. Return the new state and count; the client uses `useOptimistic`.
- Stamping must be one transaction: upsert `Passport` by `deviceId`, apply `applyStamp`, insert `Stamp` only when `added`, and on `justCompleted` write `completedAt` and a `generateRedeemCode()` result, retrying on a unique violation up to 5 times. Redirect 303 to `/paspor?stempel=CODE` or `?sudah=CODE`; unknown token redirects to `/paspor?salah=1`.
- `rankQuestions` treats a display name that is empty after trimming as anonymous. Store null, never an empty string.
- Floor map: SVG `viewBox="0 0 1200 680"`, rendered at 1200px wide inside `overflow-auto` with a fit-to-width default on phones and a Perbesar / Perkecil toggle. Each booth has an invisible 44 by 44 hit rect. Multi-unit tenants keep separate unit rects plus one label across the union on the large view. `?kategori=` dims non-matching booths to `var(--map-dim-opacity)`; `?booth=` highlights with `var(--map-highlight)` at stroke-width 3 and scrolls into view.
- Tenant page increments `viewCount` inside `after()` from `next/server`, never in the render path.
- `Event` is a singleton with `id: 1`; read it once per request with `findUniqueOrThrow`.
- `next start` must bind to `process.env.PORT`. Health check path is `/api/health`.
- Build links for `/b/` from the request host (headers), never from an env var.
- Prisma on Railway: `prisma migrate deploy` in the start command, never `migrate dev`. Generate the client in `postinstall`.
