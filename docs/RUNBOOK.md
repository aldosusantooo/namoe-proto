# Namoe Go runbook

How the deployed prototype runs and how to drive the demo. Everything here is outside the code: Railway settings, the organizer URL, the tenant magic links and the demo links. Updated at the end of implementation session B (8 Sep 2026).

## Environment variables

Railway's web service needs exactly two variables. Nothing else is read by the app.

| Variable | Value |
|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}`, the reference to the Postgres plugin so the service uses the private network URL |
| `ORGANIZER_SECRET` | A random string. Generate one with the command below and use the same value locally in `.env` |

```bash
openssl rand -hex 12
```

The local `.env` uses the Postgres plugin's `DATABASE_PUBLIC_URL` as `DATABASE_URL` so local development and Railway share one database. There is no `TZ` and no `DEMO_NOW`: the app never reads the clock and formats every time explicitly in Asia/Jakarta.

## Build and start

`railway.json` in the repo root drives both. Railway runs them on every push to `main`.

- Build: `pnpm install --frozen-lockfile && pnpm prisma generate && pnpm build`
- Start: `pnpm prisma migrate deploy && pnpm db:seed --if-empty && pnpm start`
- Health check path: `/api/health` (returns `{"ok":true}` when the database answers)

`pnpm build` first runs `scripts/tokens-to-json.ts` (also on `postinstall`), which reads `docs/tokens.css` and writes `lib/tokens.generated.json`. The placeholder route and the QR sheet read colours from that file; nothing else in `app` or `components` carries a hex value. `pnpm start` runs `next start -p ${PORT:-3000}`, so it binds to the port Railway assigns. The seed only runs when the Tenant table is empty, so a redeploy never touches live data. To re-seed on purpose, run `pnpm db:seed` locally against the same database. It upserts by slug or code, keeps existing booth and tenant tokens, and never touches tenant photos or logos.

## Placeholder art

`/img/<slug>?v=card` (600 x 600), `?v=hero` (1200 x 750) and `?v=thumb` (200 x 200) serve the category-coloured placeholder as SVG. The app appends `?t=<updatedAt epoch>` so a rename busts the day-long immutable cache. Unknown slugs return 404.

## Tenant magic links

Path pattern: `/t/<editToken>/edit`

Each tenant has a 20-character `editToken` in the Tenant table. The organizer panel lists every link under Tenant ("Tautan edit"). Anyone holding the link can edit that booth: photos (paste a URL or upload), logo, intro (600 characters), promo with a show or hide toggle, "Di booth ini" slots, Instagram, TikTok and marketplace links, replies and pins on Tanya tenant posts, and feed posts as the tenant. A wrong token renders a 404 with the pink mascot.

Uploads land in `public/uploads/<slug>/<random>.<ext>` (feed uploads under `public/uploads/feed/`), image types only (JPEG, PNG, WebP, GIF), 5 MB per file, checked server-side. The directory is gitignored except for `.gitkeep`. Railway's disk is ephemeral, so uploaded files disappear on the next deploy; pasted photo URLs survive. For the pitch, paste URLs.

## Organizer panel

Path pattern: `/organizer/<ORGANIZER_SECRET>`

Every other value in that segment returns 404. Pages under it, all inside the navy sidebar shell:

- `/organizer/<secret>` Ringkasan: four counts with context, sessions per day with open-question counts, redeem lookup, first tenants
- `/organizer/<secret>/sesi` every session with question and upvote counts; `/organizer/<secret>/sesi/<session-slug>` mark answered, hide or show
- `/organizer/<secret>/tenant` all tenants with view counts, edit links, QR links, feed posts per day and visitor feed moderation; `/organizer/<secret>/tenant/<tenant-slug>` Tanya tenant and feed hide or show for one tenant
- `/organizer/<secret>/tukar` look up a passport code and mark it redeemed
- `/organizer/<secret>/booth` every booth with its `/b/` link, for simulating scans
- `/organizer/<secret>/booth/cetak` the printable QR sheet, one A4 page per booth; `?booth=A37` prints a single booth. Print from the browser; the print stylesheet drops the cream and the toolbar. QR codes are generated by `lib/qr.ts` from the request host, so print from the Railway domain, not from localhost.

## Demo stamps

Five links that fill one passport. Prefix each path with the Railway domain. Open them on the same phone or browser profile so they land on the same device cookie. The fifth link completes the passport and shows the redeem code on a coral ticket.

| Booth | Tenant | Path |
|---|---|---|
| A1 | Little Palmerhaus | `/b/deqiikpjdbl5sdl6mmul` |
| A11 | Bohopanna | `/b/k5kpggupbitafk2bxunl` |
| A27 | MOOIMOM | `/b/xaixrp2et4bokjslgnqo` |
| A52 | Oxone | `/b/yjnf7ad2mbxxih3leojn` |
| A77 | Ladang Lima | `/b/oty54s6p6j4b5hvrqgfp` |

Tokens live in the Booth table and survive re-seeding. If the database is ever recreated from empty, the tokens change: read the new ones from `/organizer/<secret>/booth`.

A fresh stamp shows "Stempel baru dari Little Palmerhaus, booth A1" and the stamp arrives tilted with the yellow burst. A repeated link shows "Booth A1 sudah ada di paspor kamu". An unknown token lands on the passport with "Kode QR tidak dikenal". Type the code from the passport into `/organizer/<secret>/tukar` and press "Tandai sudah ditukar"; the passport then shows "Hadiah sudah diambil".

## Device-local state

Cookie `nm_did` (mirrored to localStorage) identifies the device for the passport, upvotes and posts. `nm_saved` in localStorage holds the "Simpan" list of tenant slugs; `nm_name` remembers the display name typed into a compose sheet.

## Local development

```bash
pnpm install
pnpm dev -p 3100
```

Port 3000 is taken on Aldo's machine, so the browser preview config uses 3100. `pnpm test` runs the unit tests, `pnpm lint && pnpm build` mirrors what Railway does. Migrations are created locally with `pnpm db:migrate --name <name>` and applied on Railway by the start command. Because the local `.env` points at the shared database, anything posted, stamped or edited locally is live data: delete test rows afterwards.
